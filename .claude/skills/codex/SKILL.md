# Codex に任せる

Claude Code のトークンを節約するために使う。節約になるのは、Codex の途中経過や長い差分を Claude Code の文脈に入れないときだけ。読むのは最後のまとめと `git diff --stat` に限る。

## 任せる作業・任せない作業

分け方は「画面の見え方に関わるか」。内部の動作は Codex のほうが速くて得意なので、まず Codex に回す。

- 任せる（見た目に関わらない内部の動作）:
  - 当たり判定・ダメージ・スコア・倒したときの処理の中身（演出の見え方は除く）
  - 敵の状態と判断、出現、難易度、ステージの流れ、罠の種類と間隔
  - 移動の計算、入力とパッドの割り当て、記録とセーブ、マルチプレイ
  - ビルドや型のエラー、性能の改善、リファクタリング
  - 「どこで〇〇しているか洗い出して」のような調べもの、差分のレビュー
- 任せない（Claude Code がやる）:
  - モデリング（武器・敵・ステージの形）
  - モーション（攻撃の動き、手元の武器の動き、敵の姿勢やよろめき、カメラ演出）
  - UI（HUD・メニュー・武器選択などの見た目と配置）
  - 当たりの光・切り跡・ポストエフェクトなどの見た目の演出
- 両方にまたがる作業（例: 新しい攻撃を足す）は分ける。Claude Code が動きと見た目を作り、当たり・ダメージ・状態の処理を Codex に渡す。順番が要るときは、Claude Code の作業をコミットしてから渡す。

## 1. 指示を書く

短く、言い切る。Codex は `AGENTS.md` を自分で読むので、決まりを書き写さない。入れるもの:

- 何が起きていて、どうなればいいか
- 見るべきファイル（わかっていれば）
- 触ってはいけない範囲（いま Claude Code が作業中のファイルなど）
- 「終わったら `npm run build` を通し、変えたファイル・確かめたこと・確かめていないことを 10 行以内でまとめて」

## 2. 動かす

まとめは `-o` でファイルに書かせ、標準出力はログに捨てる。長くかかるので `run_in_background` で回し、終わりの通知を待つ（ポーリングしない）。

```powershell
$dir = "$env:TEMP\codex-runs"; New-Item -ItemType Directory -Force $dir | Out-Null
$id = Get-Date -Format "yyyyMMdd-HHmmss"
codex exec -s workspace-write -o "$dir\$id.md" "<指示>" *> "$dir\$id.log"
"$dir\$id.md"
```

- 作業: `-s workspace-write`（リポジトリの中だけ書ける）。
- 調べもの: `-s read-only`。
- レビュー: `codex exec review --uncommitted -o "$dir\$id.md" *> "$dir\$id.log"`。コミット済みのブランチなら `--base main`。
- 同じファイルを Claude Code も触っているときは、先にユーザーにコミットしてもらうか、触らない範囲を指示に書く。

## 3. 結果を見る

1. `$id.md`（まとめ）を読む。
2. `git diff --stat` で、変わったファイルが指示の範囲に収まっているか見る。
3. 全文の差分は読まない。まとめに不安な点があるとき、または範囲の外のファイルが変わっているときだけ、そのファイルの差分を読む。
4. `.md` が空、または失敗しているときだけ `$id.log` の最後の 40 行くらいを読む。
5. ユーザーには、まとめと確かめ方の URL を短く伝える。コミットは頼まれたときだけ。
